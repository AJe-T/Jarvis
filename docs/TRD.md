## 5. Non-Functional Requirements

### 5.1 Performance budgets

| Metric | Target |
|---|---|
| Cold start → window interactive | < 3 s |
| Idle RAM (all processes, voice armed) | < 450 MB |
| Idle CPU (wake word armed) | < 3% of one core |
| Wake word detection → LISTENING state | < 300 ms |
| End of speech → transcript final | < 800 ms |
| Typed message → first token (p50) | < 1.5 s |
| End of speech → first TTS audio (p50, no tools) | < 2.5 s |
| Native SAFE tool execution (p95) | < 500 ms |
| Vault edit → re-indexed | < 5 s |

### 5.2 Reliability

- Agent loop hard cap: **25 iterations** per user turn (computer mode: 60), then stop and report.
- Every external call has a timeout (Claude: 120 s stream idle 30 s; MCP tool: 60 s; PowerShell: 30 s; STT connect: 5 s).
- Retries: exponential backoff with jitter for 429/5xx/overloaded (max 3), **never** retry non-idempotent tools automatically.
- Crash isolation: MCP servers run as child processes; a crash marks the server "error" and doesn't crash the app.
- Graceful degradation matrix:

| Failure | Behaviour |
|---|---|
| No network | Banner "Offline"; voice capture still works; queue nothing; SAFE local tools available via typed slash-commands (P1) |
| Claude API error | Show error card with retry; spoken "I'm having trouble reaching my brain, sir." |
| STT provider down | Fall back to alternate provider if configured; else text-only mode |
| TTS provider down | Fall back to Windows SAPI |
| Vault missing | Recreate folder skeleton, warn once |
| DB corrupted | Restore from latest automatic backup ([Database](Database.md) §7) |

### 5.3 Security & privacy (summary — see [Security](Security.md))
- Electron hardening: `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, strict CSP, no `remote`, IPC sender validation.
- Secrets encrypted with `safeStorage` (DPAPI on Windows); never sent to renderer.
- No inbound network listeners; MCP over stdio or outbound HTTPS only.
- Deterministic permission policy; LLM cannot change tiers.

### 5.4 Observability
- Structured logs (pino) to `%APPDATA%/Jarvis/logs`, rotated daily, 14-day retention, secret redaction.
- Tamper-evident audit log in SQLite (hash chain) for every tool decision.
- Usage ledger (tokens, est. cost) per request.
- Debug panel (dev builds): raw Claude request/response viewer with secrets masked.

### 5.5 Accessibility & UX
- Full keyboard operation; visible focus; `prefers-reduced-motion` respected; WCAG AA contrast on text ([Design-system](Design-system.md)).

## 8. Architecture Decision Records (condensed)

### ADR-001: Electron over Tauri
| | Electron | Tauri |
|---|---|---|
| Language | TS only | TS + Rust |
| Size/RAM | Heavier (~150 MB installer) | Light |
| Ecosystem for this app (nut.js, Picovoice, MCP SDK, better-sqlite3) | Native Node support | Requires sidecars |
| Team familiarity | High | Low |

**Decision:** Electron. Footprint is acceptable for a single-user desktop app; one language beats binary size. **Revisit** if RAM budget is consistently exceeded.

### ADR-002: TypeScript-only (no Python backend)
Python has richer automation libraries (pywinauto, UFO), but a second runtime doubles setup and packaging complexity for a beginner. **Decision:** TS only; Python-based tools (e.g., Windows-MCP) are allowed as optional, external MCP servers.

### ADR-003: SQLite + Obsidian (dual store) over a vector DB
SQLite holds structured/raw data (messages, tool calls, usage) and the FTS index; the vault holds curated, human-editable memory. Vector search is deferred (P2: `sqlite-vec` + local embeddings) because FTS5 + core-profile injection is sufficient for a single user's memory scale. **Consequence:** vault is the source of truth for memories; DB index is rebuildable from it.

### ADR-004: Claude memory tool mapped to the vault
Anthropic's client-side memory tool lets Claude decide what to read/write as files. Mapping its `/memories` root to `JarvisBrain/Memory/` gives Obsidian integration for free. A Haiku "curator" adds automatic extraction because the main model may not always save on its own.

### ADR-005: Playwright MCP for the browser (v1), Claude browser-use toolset later
Playwright MCP is ready-made (no executor to write). The first-party browser toolset has 27+ member tools to implement, which is valuable but heavy. **Revisit in P2.**

### ADR-006: Native PowerShell tools first, computer-use second
Deterministic tools (open app, volume, files) are fast, cheap, and reliable. Screenshot-based computer use costs thousands of tokens per step and is slower, so it is used only when no native tool or MCP server fits.

### ADR-007: Main-process audio pipeline
Mic capture, wake word, and STT streaming run in the main process (PvRecorder + Porcupine + provider WebSocket), so **no secrets enter the renderer**. The renderer only receives audio levels (for the orb) and TTS audio buffers to play.

### ADR-008: Deterministic policy engine
Permission tiers are enforced by code before any tool executes. The model is told the rules but has no ability to change them. This is the core safety property of the product.

### ADR-009: Built-in `node:sqlite` instead of `better-sqlite3`
`better-sqlite3` 13.0.3 has no prebuilt binary for Electron 44 (ABI 149), so it would have to be compiled with the Visual Studio C++ Build Tools, and node-gyp warns that the space in the user path (`C:\Users\TEJA N`) can break native builds. Electron 44 ships Node 24.21, whose built-in `node:sqlite` (`DatabaseSync`, SQLite 3.53) is synchronous like better-sqlite3 and has FTS5 + the porter tokenizer compiled in (verified 2026-10-06). **Decision:** use `node:sqlite` (approved by Sir). **Consequences:** no native DB module to rebuild; backups use `VACUUM INTO`; transactions use a small `BEGIN`/`COMMIT` helper. **Revisit** if Electron drops `node:sqlite`. System Node 22's `node:sqlite` lacks FTS5, so `npm test` runs Vitest on Electron's bundled Node (`scripts/vitest-electron.mjs`, `ELECTRON_RUN_AS_NODE=1`), the same runtime the app uses.

### ADR-010: Optional "Claude subscription" connection via the Claude Agent SDK
Sir has a Claude Pro plan and Claude Code, but no API key. **Decision (approved by Sir, personal use only):** Settings → Models & AI offers two connections, one active at a time (`llm.provider`): *Anthropic API key* (default, Messages API, unchanged) or *My Claude subscription*, which drives Sir's own installed, unmodified Claude Code (`%USERPROFILE%\.localin\claude.exe`, else PATH) through `@anthropic-ai/claude-agent-sdk` 0.3.291. Sign-in happens only through Claude Code's own `claude auth login`; Jarvis never reads, stores or forwards Claude credentials and strips `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN` from Claude Code's environment so usage can't silently switch to API billing.
Checked against code.claude.com/docs/en/legal-and-compliance (2026-10-07): OAuth is for "ordinary use of Claude Code"; third-party developers may not offer Claude.ai login in their products, but the terms do not prevent "an end user from signing in to the unmodified Claude Code binary with their own Claude subscription". **This mode must never be offered to other users or shipped as a product feature;** a distributed build should remove it or require API keys.
**How it works:** chat turns run in `agent/sdk-loop.ts`. Claude Code runs the tool loop; Jarvis tools are served by an in-process MCP server (`mcp__jarvis__*`) whose handlers call the normal tool executor, so the policy engine, guards, confirmations, audit log and activity rows are unchanged. Options: `settingSources: []` and `strictMcpConfig` (nothing from `~/.claude`: no CLAUDE.md, hooks, plugins, skills or MCP servers), `tools: []` (no Bash/Read/Write/Edit/WebFetch) plus `WebSearch` only when web search is on, `canUseTool` allows only Jarvis tools and WebSearch, `persistSession: false` (no transcripts in `~/.claude/projects`; `/private` stays private), an empty working folder under userData. History is sent as a text transcript each turn. Tool-less background calls (titles, summaries, curator) use `llm/claude-code.ts`.
**Consequences:** computer control (`delegate_desktop_task`) is unavailable because the computer-use toolset is API-only; each turn starts a Claude Code process (~1.5 s extra, measured 4–5 s for a full tool turn); usage counts against Sir's plan limits (shared with his Claude Code sessions); `usage_ledger.billing = 'subscription'` rows show an API-equivalent cost but are excluded from the dollar budget; prompt caching is Claude Code's, not Jarvis's. The SDK's bundled 240 MB Claude Code binary is excluded from the installer.


### ADR-011: On-device voice engines (Whisper + openWakeWord) beside Deepgram + Picovoice
Sir wants a choice between the cloud services and local alternatives. **Decision (approved by Sir):** Settings → Voice picks the wake-word engine (`voice.wake.provider`: Picovoice "Jarvis" or openWakeWord "Hey Jarvis") and the speech-to-text engine (`voice.stt.provider`: Deepgram or Whisper) independently; Whisper size is `voice.stt.whisperModel` (base.en, small.en default, small multilingual). Everything runs inside the app on **onnxruntime-node 1.30.0** (MIT, prebuilt Windows DLLs, no compiler, no Python): Whisper through **@huggingface/transformers 4.3.1** (Apache-2.0; q8 encoder + merged decoder from onnx-community), openWakeWord re-implemented in TypeScript (`voice/local/open-wake-word.ts`: melspectrogram → 76-frame windows → embeddings → `hey_jarvis_v0.1` classifier, 80 ms chunks, 5 warm-up predictions, 2 s debounce) and Silero VAD v6.2.3 (MIT) to find the end of speech.
**Models** download on first use from pinned revisions (Hugging Face commit SHAs, openWakeWord v0.5.1 release, Silero v6.2.3 tag) and are verified against SHA-256 hashes in `voice/local/models.json` (generated by `scripts/make-model-manifest.mjs`), then kept in `userData/models`. transformers.js runs with `allowRemoteModels = false`, so nothing else is fetched. The openWakeWord model weights are **CC BY-NC-SA 4.0 (non-commercial)**: fine for Sir's personal use, not for anything sold.
**Measured on Sir's PC (i7-10610U, no GPU), with SAPI-synthesised speech:** "Hey Jarvis" scored 0.998 and fired; unrelated speech scored 0.000; wake-word CPU ≈ 3–5 % of one core. Whisper small.en returned "What time is it in London right now?" ≈ 3 s after the audio (base.en ≈ 1.5 s), plus the 0.7 s end-of-speech wait. Model loads: wake word 0.3 s, Whisper base.en + VAD 2 s (preloaded when selected).
**Consequences:** no live partial transcript with Whisper (it transcribes after Sir stops); short hallucinations ("Thank you.") on near-silence are dropped; the installer grows by the Windows onnxruntime and sharp DLLs (linux/darwin binaries and onnxruntime-web are excluded).

### ADR-012: Conversational voice (follow-ups, echo rejection, always-listening)
Sir reported that voice "interrupts after thinking and isn't like a conversation". Causes found in his data: every voice turn started a new conversation; a wake word (or false trigger) while Jarvis was thinking cancelled the reply; Jarvis's own voice and one-word mishearings were sent as requests. **Decision:** voice turns continue the same conversation for 15 minutes; a running reply is replaced only when real words arrive; after a spoken reply a silent follow-up window (`voice.followUpSeconds`, default 6) needs no wake word; transcripts that repeat Jarvis's recent speech in order are dropped as echo; one-word unclear transcripts get "didn't catch that". New voice mode **ambient** ("Always listening", on-device Whisper only): every phrase is transcribed locally into a 2-minute in-memory buffer; saying "Jarvis" anywhere in a sentence, or speaking in the follow-up window, asks a fast-model **intent judge** (purpose `intent`) whether it is addressed to Jarvis and what the self-contained request is. Ideas from isair/jarvis's transcript-first listening; code is ours. **Consequences:** ambient mode costs one small model call per mention; nothing is stored; Whisper backlog is bounded (oldest dropped).

### ADR-013: Local model connection (Ollama / LM Studio)
**Decision:** a third connection, `llm.provider = 'local'`, talks to any OpenAI-compatible server on this PC or the home network (loopback/private addresses only, because the whole conversation is sent). An adapter translates Messages-API requests (tool_use/tool_result, images) to `/chat/completions` and the SSE stream back, so the normal agent loop, tools and policy run unchanged; `<think>` reasoning is hidden; web search and computer control stay API-only. Local calls are recorded with billing `local` at zero cost. **Consequences:** quality and tool-calling depend on the model Sir installs (Qwen 3, Llama 3.1+); Ollama is not installed by Jarvis.

### ADR-014: Skills in the agentskills.io format
**Decision:** adopt OpenJarvis's skills idea using the open SKILL.md format: a folder with frontmatter `name` + `description` and instructions, plus text reference files, installed from a folder or a public GitHub folder into `userData/skills`. Enabled skills are listed (name — description) in the dynamic context; `use_skill` loads the instructions on demand and `read_skill_file` reads a file (path-traversal safe). Skills never execute code; scripts are readable text only. **Consequences:** a malicious skill can only influence Claude's text, and every action still passes the policy; Sir reviews skills in Settings.

### ADR-015: Scheduled agents (briefing, tasks, check-ins)
**Decision:** a `scheduled_tasks` table and a 30-second ticker run prompts as ordinary turns in their own conversation (purpose `briefing`/`task`), while Jarvis is running. Kinds: briefing (spoken + saved to `Briefings/`), task, checkin (reply `NOTHING` = silent, conversation deleted). Runs missed by more than 2 h are skipped. A switched-off Morning briefing preset ships; `schedule_task` (CONFIRM) lets Sir create tasks by asking. Ideas from OpenJarvis's morning digest / monitors / proactive agent. **Consequences:** confirmations during unattended runs time out (deny) if Sir is away.

### ADR-016: Deep research agent and fetch_web_page
**Decision:** `deep_research` runs a separate agent loop on the current connection with only reading tools (web_search, fetch_web_page, search_memory), returns a cited Markdown report and saves it under `Research/`. `fetch_web_page` reads public pages only (every redirect re-checked by the URL guard), caps at 2 MB, converts HTML to text, and marks output untrusted. Ideas from OpenJarvis (deep_research) and isair/jarvis (fetch_web_page).

### ADR-017: Telegram channel
**Decision:** Sir's own bot (token secret `telegram`), long-polled; only the one private chat paired with a 6-digit code is answered (`telegram.chatId` is main-only). Messages are normal turns; confirmations arrive as inline buttons recorded as `user_remote`; **destructive actions can never be approved from the phone**; `/stop` triggers the kill switch; briefings can be forwarded. From OpenJarvis's 35 channels, only Telegram was built (Sir's choice). **Consequences:** replies pass through Telegram's servers.

### ADR-018: Reply copilot (desktop take on jev-chat-jarvis)
**Decision:** a hotkey or `help_me_reply` reads the chat on screen from one screenshot, Sir picks scene/relationship/dispute, Claude analyses the situation and offers stances, drafts two replies, and checks each (hard problems block, confirm-only problems flag, S = 0.7·G + 0.3·E with a missing required item capping G at 3, Top pick only when clearly ahead). "Paste into chat" re-focuses the same window title and pastes; Jarvis never sends. Ideas from jev-chat-jarvis (MIT); code is ours. **Consequences:** one-to-one chats only; screenshot reading quality depends on the app's layout.

### ADR-020: Instant commands, HuggingGPT, everyday plugins (v1.4)
Sir reported voice "interrupting after talking" and not feeling like a conversation. Causes found in his log: ambient mode kept a disposed Whisper model after a model switch (457 phrases failed with "Session already disposed"); in wake mode the mic heard Jarvis's own voice and the wake word cut him off mid-reply; endpointing (300 ms Deepgram / 700 ms Whisper) cut Sir off mid-sentence; PTT replies had no follow-up window; spoken replies were capped at 1–2 sentences with details pushed to the screen. **Decision:** ambient looks up the current Whisper per phrase; the wake word is ignored while Jarvis is audible unless `voice.bargeIn`; `voice.endSilenceMs` (default 1000) drives every engine; follow-ups also in PTT; the voice prompt asks for spoken answers. From three more repos (ideas only, no code): **Priler/jarvis** instant commands (routine triggers, time, date) answered without the model through a `direct` turn that still runs the tool through the policy; **microsoft/JARVIS** HuggingGPT as `find_ai_models` + `run_ai_model` on Hugging Face's HF Inference provider (file upload and image generation CONFIRM); **sukeesh/Jarvis** plugins that need live data or the OS (currency, markets, network, password to clipboard, folder organiser). Plugins Claude can do itself (jokes, games, maths, conversions, translation) get no tool. **Consequences:** a new secret (`huggingface`, redacted as `hf_…`); external keyless APIs (Frankfurter, CoinGecko, Yahoo chart, ipify, Cloudflare) may drift ⚠️.

### ADR-021: The rest of isair/jarvis (v1.5)
Sir asked for every isair/jarvis capability JARVIS lacked. Already present from 1.3: conversational listening, intent judge, echo rejection, follow-ups, dictation, weather, meals, screenshot, local models, fetch_web_page. **Added (ideas only, code ours, the licence is non-commercial):** hybrid memory search (FTS5 + on-device all-MiniLM-L6-v2 via transformers.js, vectors in SQLite, reciprocal-rank fusion, brute-force cosine); date-scoped conversation recall; screen OCR with Windows.Media.Ocr instead of Tesseract (nothing to install); `get_world_time` (Open-Meteo zone + Intl); chat rewind/regenerate; keyword tool routing for local models (≤ 12 tools, core + already-used kept); a Logs view; a slow-Whisper warning; Chrome DevTools and YouTube-transcript MCP presets (pinned). **Not ported:** Piper TTS (needs an espeak-ng phonemiser; Edge + SAPI cover voice out), hold-to-talk / double-tap dictation (Electron global shortcuts have no key-up; needs a native keyboard hook), the self-updater (needs signed GitHub releases), the knowledge graph and reply evaluator (the Obsidian vault, curator and Claude cover them), Low Power Mode and the VRAM-based model wizard (Ollama-specific). **Consequences:** a 24 MB optional download; vectors grow ~1.5 KB per message.

### ADR-019: The Bible and a generated reference
**Decision:** `docs/BIBLE.md` is the single human guide to the whole project, shown in-app (Bible view with search and contents). Facts that drift (tools, tiers, settings, IPC channels, migrations) live in `docs/REFERENCE.md`, generated from the code by `npm run docs:reference`; a unit test fails when it is stale.

### ADR-022: Phone-keyboard dictation in the composer (v2.0)
Sir: "the voice one is not working properly… like Android: tap the mic, words appear in the box in real time, then I send." ### ADR-027: Laya as an on-device filter in front of the intent judge (v2.5)
Sir asked to integrate [Laya](https://github.com/NandhaKishorM/laya) (Apache-2.0), a non-generative model that answers typed questions (choice / score / yes-no) over text in one forward pass. **Decision:** run it in the main process with `laya-ts` on the existing `onnxruntime-node` (ADR-002: no Python at runtime). `laya-ts` is not on npm, so it is built from the `v0.4.0` tag (commit 3cf26cb; the `v0.4.1` source has a syntax error in `hooks.ts`) and vendored as `vendor/laya-ts-0.1.0-3cf26cb.tgz`. The model is `laya-multilingual` (mmBERT-base) exported to fp32 ONNX by laya's own `export_onnx.py` (torch vs ONNX checked within 1e-4), pinned by SHA-256 in `models.json`. It answers one question: *who is the newest phrase spoken to, Jarvis or someone else?* `laya.mode` = off (default) / shadow (run beside Claude, log only numbers) / on (skip the Claude judge below 0.3; phrases that start with "Jarvis" always go to Claude). **Measured on this PC (CPU, 2026-10-10):** ~0.3 s per question, ~6 s load (~10 s with the per-load SHA-256 check), ~850 MB RAM, 1.32 GB on disk; all 10 phrases meant for Jarvis scored ≥ 0.67 (English, Hindi, Telugu, follow-ups), 3 of 4 phrases *about* Jarvis scored < 0.3. **Rejected:** (1) model routing by Laya's difficulty score: zero-shot scores barely separated "hi" from "design a database" (0.8 vs 1.9 of 3), so it would have sent requests to the wrong model; (2) a yes/no question over the whole transcript: no threshold separated the cases; (3) int8 quantisation (386 MB): scores moved by up to 0.7 against fp32; (4) the Python `laya-mcp-server` / `laya-serve`: a Python runtime and Claude would call it as a tool, after the cost it is meant to save. **Consequences:** no in-app download until the ONNX files are hosted (install with `npm run laya:install <folder>`); the sample is small, so shadow mode comes before on; fine-tuning on Sir's own phrases is the route to better accuracy.

### ADR-028: Better voices: Kokoro on-device and ElevenLabs cloud (v2.7)
Sir asked for the best voice model available. **Decision:** keep Edge as the default and add two opt-in engines. (1) **Kokoro-82M** (Apache-2.0), the best-rated open TTS model of its size, run in the main process on the existing `onnxruntime-node` (ADR-002) from onnx-community's ONNX export, pinned by SHA-256 in `models.json` (model + 7 voice packs, 329 MB). Phonemes come from **eSpeak NG**; its library is GPL-3.0, so it is not bundled (no `kokoro-js`/`phonemizer`, which embed it): Jarvis finds Sir's installed `espeak-ng.exe` (Program Files or PATH, never a setting) and runs it with `execFile` and an argument array, one call per sentence. **Measured on this PC (CPU, 2026-10-10):** fp32 at 4 threads 3.5–3.8 s for 6.8 s of audio (about 0.55× real time), int8 10–11 s (rejected: slower), 8 threads 4.2 s, DirectML 6.6 s after a 100 s first-run compile (rejected); eSpeak 0.1–0.2 s per sentence. (2) **ElevenLabs** `POST /v1/text-to-speech/{voice_id}/stream` with `xi-api-key`, `eleven_v4_turbo` by default (verified against elevenlabs.io docs 2026-10); key in the secret store; the spoken text leaves the PC, so it is opt-in. **Fallback:** the chosen engine → Edge → SAPI, toast once with the reason. **Rejected:** Fish Audio (ethanplusai/jarvis's choice; ElevenLabs covers cloud), Piper (GPL now, older quality), a Python Kokoro server (a second runtime). **Consequences:** Kokoro's first words take 1–2 s on a laptop CPU; Telegram voice replies stay on Edge (they need MP3).

### ADR-029: On-device models run in their own process (v2.9)
After 2.8 Sir reported the app "very lagging". **Cause (measured):** `onnxruntime-node` 1.30 runs `InferenceSession.run()` and session creation synchronously on the calling JS thread (its `run` only defers with `setImmediate`). Whisper (transformers.js), Kokoro and Laya all ran in the Electron main process, which on Windows also pumps window messages and every IPC reply, so each transcription, each spoken sentence and each Laya decision froze the whole app. On this i7-10610U (4 cores / 8 threads) with whisper-base.en: main-thread stalls of 1.6 s (Whisper load), 0.9 s (a 3 s transcription), 2.8 s (one Kokoro sentence); Sir's setting was whisper-small.en, which is slower still (the log showed "speech recognition is slower than real time"). **Decision:** a single Electron `utilityProcess` ("Jarvis models", `out/main/inference-host.js`) hosts Whisper, Kokoro sessions and Laya; main talks to it by request id (`inference/client.ts`), typed arrays cross by structured clone, and the process runs at `PRIORITY_BELOW_NORMAL` so Windows serves the UI first. Every request carries what its model needs to load, so a crashed host restarts on the next request and reloads lazily. Model threads are capped at half the logical cores (max 4). Silero VAD and openWakeWord (tiny, single-threaded, every 32/80 ms) stay in main: a process hop per frame would cost more than it saves. Tests and plain Node fall back to in-process models (`process.type !== 'browser'`). **Measured after:** max main-thread stall 55 ms across Whisper load, transcription and Kokoro synthesis. Also the idle orb draws at 30 fps (full speed when Jarvis listens, thinks, acts or speaks). **Rejected:** worker_threads (no priority control; a crash takes main down), DirectML (100 s first compile, slower for Kokoro, ADR-028). **Consequences:** about 100–200 MB more RAM for the second process; Whisper small.en is still slower than real time on this CPU, so base.en stays the recommendation.

### ADR-030: Fast path for plain PC commands, and what Laya can do (v2.9)
Sir asked whether Laya could handle every conversation and all OS control to make Jarvis faster and cheaper. **Finding:** Laya is a classifier (choice / score / yes-no over text in one forward pass); it generates no text, so it can't answer, plan or call tools with arguments, and can't replace Claude. **Decision:** use it where a choice is enough. A fast path in the orchestrator, for Sir's own plain requests (purpose chat, no attachments, typed or spoken): (1) exact rules for commands with a value (`open <app>` up to 3 words without folder/file/and…, `volume N`, mute/unmute, media keys, lock); (2) when `agent.fastCommands = laya` and Laya is loaded, one choice question over argument-less actions (play/pause, next, previous, mute, unmute, other) for requests of ≤ 9 words, accepted only at ≥ 0.85 and ≥ 0.5 ahead of the runner-up. A hit runs one SAFE tool through the existing `directTurn` (policy, audit, history), with no model call. Only the tool name and probability are logged. Laya now loads when either the listening filter or the fast path wants it (the fast path doesn't depend on the assistant's name). **Rejected:** Laya for model routing (ADR-027 measurements), extracting free text (Laya has no span answers), fast-pathing non-SAFE tools (they need confirmation anyway). **Consequences:** saves a full Claude turn (system prompt + tools) on the commonest commands; a mis-match costs one wrong media key at worst.

### ADR-032: Jarvis Apps (v2.9)
Sir asked for built-in apps (browser, timer, command prompt and others) that Jarvis uses and he can use. **Decision:** sidebar → Apps. **Browser** and **Terminal** get their own windows because of Security.md §7: app windows never load remote content, and the main renderer must never gain an unconfirmed way to run commands. The Browser is a `BaseWindow` with two `WebContentsView`s: a local address bar (own preload: go, back/forward, reload, stop, home) and the page (separate persistent partition `persist:jarvis-browser`, sandboxed, no preload, all permissions denied, http/https only, popups load in place). Jarvis reads the page's visible text in an isolated world (the page can't fake it) and it is wrapped as untrusted content. The Terminal is a local page whose preload can only run/stop/list/clear; main answers only that window's `webContents`. Commands run as the standard user through the existing PowerShell runner with the shell guard, a 60 s limit, 20 KB output, the working folder passed as a parameter (so `cd` persists), and an audit entry; every `run_powershell` Jarvis runs is mirrored there. **Timers** (scheduler-backed countdowns, live list with cancel, stopwatch), **Scratchpad** (`apps.scratchpad` setting, 20,000 chars; tool can read/append, clear asks) and **System monitor** live in the Apps view. Tools: `open_jarvis_app`, `jarvis_browser`, `scratchpad`. **Rejected:** a `<webview>` in the main window (webviewTag is off), reader-mode only (no logins or JS sites), a terminal panel inside the main window (renderer compromise → code execution without confirmation). **Consequences:** the Browser's cookies persist in its own partition (clear by deleting `Partitions/jarvis-browser` in the user-data folder).
### ADR-033: Chat artifacts in a sandboxed frame (v2.12)

### ADR-045: AI Router, a free pool of providers in three tiers (v2.29–2.34; amends the "never switches models silently" rule of integrations step 4, and in 2.31 the "custom public endpoint: unsupported" rule for tier 3 only)
**Context:** Sir uses FreeLLMAPI (tashfeenahmed/freellmapi, MIT) to pool free tiers and wants the same inside Jarvis, with Claude as the boss deciding what free models may do. **Decision:** a sidebar module (AI Router) and a brain `free` behind which our own router picks a route (connection + model) per request, skips routes over a known cap or paused, fails over on 429/5xx with cooldowns learned from `retry-after` and Groq's `x-ratelimit-*` headers, and records each attempt in `pool_calls`. Tiers are by who receives the text: 1 Claude and the local model (private data allowed), 2 trusted free providers, 3 third-party relays (asked first). Private data never leaves tier 1, enforced in code (Security.md §16.15). Switching models is allowed but always visible (the trail in every answer). Built in four phases; Phase 1 (2.30) is the free brain, limits, failover, Priority and Balanced, key checks, `.env` import, the privacy rule and the tier-3 question. **Rejected:** bundling or proxying FreeLLMAPI (Sir keeps using it separately; Jarvis already connects to it as a local server), using its signed catalogue feed (its paid service), a fixed per-model limits table (Groq and Gemini publish free limits only in the signed-in console; checked 2026-10-27), and Cloudflare for now (its address contains the account id). Ideas from FreeLLMAPI's router and quota engine; our own code. **Amendment (2.31, Sir's decision 2026-10-27):** (1) *Custom providers*: Sir may add OpenAI-compatible relays (e.g. Pollinations) by address, for basic non-private questions. They are always tier 3 and get only the question (no prompt, history, pictures or tools); answers are untrusted like a web page; HTTPS public host names only, DNS re-checked before every call, no redirects, address fixed after saving, key in DPAPI (Security.md §16.15). The main brain and tier 2 keep catalogue-only addresses; the "Custom public endpoint" row of Integrations.md stays unsupported for them. Plus `pool.tier3EveryTime`. (2) *Cloudflare Workers AI* joins tier 2: its catalogue address keeps a single `{account_id}` slot that code fills from a setting validated as 32 lowercase hex characters, and `checkCloudUrl` accepts only that shape, so the address stays fixed. **Rejected:** letting a custom provider be tier 2 (its operator is unknown), DNS pinning through an undici dispatcher (would need a direct undici dependency matched to Electron's own fetch; the re-check before each call plus question-only requests cover the risk), and a free-text Cloudflare address. **Amendment (2.32, Phase 2 "Claude as the boss", Sir's decisions 2026-10-27):** six rules, each a setting `pool.delegation.*`: (1) `delegate` (on): `delegate_task` tells Claude to use brain `free` for heavy non-private work and ask for a short report; off refuses `free` there. Tier 2 only; public lookup tools only. (3) `sticky` (on): the pool remembers the route that last answered each conversation for 30 min (in memory) and tries it first. (4) `handover` (on): a different model gets a note built in code (the last 2 free-AI exchanges, 400 characters each, then the question); off: the question alone. (6) `budgetAware` (on): past 80% of today's budget (API key only), the front door opens and Claude's context says to delegate. Pool runs use a free budget guard (per-turn token ceiling only), so Claude's budget no longer stops delegations. `questionOnly` now sends a tier-3 route the newest user text (the current question) instead of the first. **Rejected:** a model-written hand-over note (an extra call per switch for little gain), letting the front door use tier 3, sending a front-door chat Claude's earlier replies, and a Laya "approve" (rules decide; Laya can only send a question back). **Amendment (2.33, Phase 3 "Abilities", Sir's decisions 2026-10-28):** four abilities, each a setting `pool.abilities.*`, each behind the same privacy gate in code (`privateBlock`/`poolBlock`, asked before every request leaves the PC). (1) *Free search*: native tool `free_web_search` tries Tavily → Brave Search → Exa → Firecrawl → Linkup with one DPAPI key each; limits learned from replies (`llm/pool/limits.ts`); results untrusted. (2) *Images*: tool `generate_image` and the Abilities tab's Generate (`pool:image`): Cloudflare Workers AI FLUX.1 [schnell] (tier 2, square), then Pollinations (tier 3, asks first via the shared `mayUseTier3`); saved to `<vault>/Images/` with a credit note. (3) *Fusion*: brain `fusion` for `delegate_task` and Compare AIs: up to 3 drafters, one per tier-2 provider (`PoolJob.pick` narrows the router's ranking), and a judge (largest model, non-drafting provider first); tier 2 only, no tools; if one draft comes back it stands alone, and if no judge is free the first draft stands, both said in the trail. (4) *Voice backup*: speaking Kokoro → Edge → ElevenLabs → Windows (on); hearing Whisper on this PC → Groq → OpenAI (off by default, confirm to switch on, audited), phrase mode while on; every engine change posts a named notice and the page shows the engine in use. **Rejected:** Gemini image models (no free image quota, checked 2026-10-28), Cloudflare models with sizes (Lucid Origin costs about 2,500 neurons a picture; FLUX.2 Klein's input isn't documented), tools for fusion drafters (3× tool calls, slower), sending image prompts to tier 3 without asking, cloud hearing on by default (Sir's recorded voice), and hiding `web_search` with no turn context (the catalog still lists both). **Amendment (2.34, Phase 4 and the merge, Sir's request 2026-10-28):** (1) *Strategies*: `rankRoutes` takes any `RoutingStrategy`; non-Priority strategies rank by `weightedScore` (reliability, speed, smarts, `STRATEGY_WEIGHTS`; Custom from `pool.weights`), shrunk near a route's caps as before. (6) *Analytics* (`llm/pool/analytics.ts`, IPC `pool:analytics`): from `pool_calls` (now kept 92 days); outlook per provider from the roomiest capped route's daily use and the pace since 00:00 UTC. (7) *Test this model* (IPC `pool:testModel`): one real "Reply with OK" per tier-2 door, recorded and learned from like any request; tier 3 never. ### ADR-046: Forge, Jarvis builds changes to itself (v2.36, phases F1–F2; plan in Forge.md)
**Context:** Sir wants to stop hand-coding features: give Jarvis a goal, a repo or an app to study, and get a tested build back. Jarvis already drives Sir's Claude Code through the Agent SDK (ADR-010) and opens sessions with REA (ADR-031), but those run in a window and ask Sir for every permission. **Decision:** `src/main/forge/`. One clone Forge owns (`<userData>/forge/repo`, from a github.com repo Sir sets with `forge_setup`), a fresh branch `forge/<slug>` from `origin/dev` and a fresh `npm ci` per run (the checks run changed code, so nothing in `node_modules` or `.git` is trusted between runs: `.git/config` is restored from a copy taken after cloning and git never runs hooks). The boss is Claude Code headless (`query` with `tools` = Read/Glob/Grep/Edit/Write/TodoWrite, shell, web and sub-agent tools also in `disallowedTools`, an allow-listed environment (`forgeEnv`), `settingSources: []`, `systemPrompt` preset + Forge rules + the repo's CLAUDE.md and RULES.md, `maxBudgetUsd` from `forge.budgetUsd`, 300 turns). No shell: checks run through an in-process MCP tool `run_check` that Forge executes with node.exe + npm-cli.js and argument arrays. `canUseTool` (`forgePermission`) keeps every file tool inside the clone (`~` paths refused, junctions resolved with realpath), off `.git`/`node_modules`, off Windows alias names (8.3, streams, trailing dots, devices) and off protected files Sir didn't name. ### ADR-044: Instant wake word by open-vocabulary keyword spotting (v2.28; amends ADR-011, ADR-043)
**Context:** Sir reported that "Hey Jarvis" took a long time to react and often wasn't heard, and that the five-phrase personal wake word didn't work well. The default engine (`name`, v2.8) transcribes every phrase with Whisper: it waits for the end-of-phrase pause (1 s), then a Whisper pass (whisper-small.en int8 on 4 cores: ~0.66 s per short command in sherpa-onnx's C++ runtime, slower in transformers.js and under load), then the greeting, and its backlog of three drops phrases when Whisper falls behind. We compared five public Jarvis projects (READMEs read 2026-10-22): isair/jarvis (faster-whisper name spotting, which lists "slow speech recognition can cause missed utterances"), Priler/jarvis (Vosk, Porcupine/Rustpotter), PanPenek/JarvisAi (openWakeWord + faster-whisper), AlexandreSajus/JARVIS (cloud Deepgram, no wake word) and Open-LLM-VTuber (sherpa-onnx among its ASR engines). The responsive ones all use a dedicated wake-word model, never a full transcriber. **Decision:** (1) New wake engine `spotter`, the new default: sherpa-onnx-node 1.13.8 (Apache-2.0, N-API with a delay-loaded node.dll, so it loads in Electron) running k2-fsa's `sherpa-onnx-kws-zipformer-gigaspeech-3.3M-2024-01-01` (Apache-2.0) in the main process, one thread, 80 ms frames, 2 s debounce. (2) Any name with no training: `word-pieces.ts` reads the model's SentencePiece `bpe.model` (our own protobuf reader) and splits each word into the most likely unigram pieces (Viterbi); it reproduces the model's own nine example keyword lines exactly. Phrases are "HEY <name>", the bare name when it has 5+ letters, and Voice Match's learned spellings. (3) Sensitivity s → threshold clamp(0.55 − 0.5 s, 0.05, 0.5); 0.6 → 0.25. Measured here on 20 voices of a 900-speaker Piper model: 75/80 "Hey Jarvis"/"Jarvis …" phrases caught (plateau from 0.25 down), 0/120 short and 0 in 9.1 min of continuous near-miss talk ("Travis", "Harvey", "harvest", "jarring") at every threshold 0.03–0.25; 20/20 for "Hey Friday" and "Hey Summer", 17/20 for "Hey Edith"/"Hey Nova", 0/20 false; fires ~0.3 s after a bare "Hey Jarvis" and before the end of longer sentences; ~1.6 % of one core. (4) Calibration: each Voice Match phrase goes through spotters at 0.50…0.05; the strictest level that still hears all but one take (four or more phrases) is saved as `voice.wake.spotterLevel` and can only lower the threshold. Cleared on rename and with Forget my voice. Enrolment keeps the spotter selected instead of switching to `personal`. (5) The model ships only as a GitHub release `.tar.bz2`: the manifest gained `archive {url, sha256, size, root}`; the store checks the archive's size and SHA-256, unpacks with our own `lib/bzip2.ts` (format decoder with per-block CRC, yields between blocks; 2.3 s for this archive, longest pause 148 ms) and `lib/tar.ts` (ustar + GNU long names + pax paths, checksums), keeps only the pinned files and checks each one's SHA-256 again. (6) sherpa-onnx bundles onnxruntime 1.28.2 and onnxruntime-node brings 1.30.0, both `onnxruntime.dll`; Windows reuses a loaded DLL by name, so `loadSpotterModel` imports onnxruntime-node first and sherpa then runs on the newer, backward-compatible runtime. `tests/integration/spotter.real.test.ts` (CI, `JARVIS_SPOTTER_REAL=1`) downloads the real model through the store, spots phrases in its recordings, and runs onnxruntime-node afterwards. (7) "Set up free on-device speech" also downloads the spotter and moves `name` to `spotter`; saved choices are otherwise kept. **Rejected:** Windows' built-in `tar.exe` for unpacking (bzip2 support isn't documented for every Windows 10 build), a bzip2 npm package (our own decoder is a few hundred lines and fully tested), a streaming Zipformer for speech-to-text (the 20M English model scored 33 % WER on the same clips against 5.6 % for whisper-small.en and 9.4 % for Moonshine base), running the spotter in the model process (a few ms per frame doesn't need it, and frames would cross processes every 80 ms), training a custom openWakeWord model (Python, hours), cloud wake words (audio would leave the PC all the time).

### ADR-043: Personal wake word from the Voice Match phrases (v2.24; amends ADR-011, ADR-039)
**Context:** Sir's log showed the "hey jarvis" openWakeWord model firing only some of the time for his Indian-English voice (it was trained on synthetic, mostly US speech), the Whisper name engine reacting slowly, and two flow bugs: a repeated wake word restarted the greeting (the mic never opened while he kept saying the name), and the first greeting of a session took 3–9 s because Kokoro rendered it cold. **Decision:** (1) Few-shot keyword spotting on openWakeWord's embedding model (Google's speech_embedding, made for this; the same idea as Snowboy personal models and EfficientWord-Net; our own code): each enrolment phrase → its 96-d embeddings every 80 ms (`phraseFeatures`), trimmed to the loud chunks + 3, mean-centred with the enrolment mean and unit-normalised; at runtime subsequence DTW (whole template, ending now, free start, cosine cost, average per step) against the last 1.6 × longest template, only within 6 chunks of speech; threshold = mean leave-one-out distance × (0.4 + 0.6 × sensitivity), clamped 0.06–0.30; 2 s debounce. With the default name the "hey jarvis" classifier runs on the same features (either fires). Templates are secret `voice_wake` (validated on load), dropped on rename and with "Forget my voice". Wake engine `personal`; enrolment switches to it unless Picovoice is chosen. A check with SAPI voices and the real models (`hey jarvis` vs "hey travis", "jarvis", other phrases) gave same-speaker distances 0.02–0.04 against 0.20+ for the nearest negative. (2) `greetThenListen` ignores a wake while greeting or listening; with echo cancellation it opens the STT session with the greeting (an empty or echoed first phrase reopens listening once; a greeting prefix is stripped). (3) `warmSpeech` renders the stock lines into the speech cache on `applyMode` and after a voice change. (4) Near misses (≥ 60 % of the classifier threshold, or < 2 × the distance threshold) are logged per phrase. (5) Startup hello from the planner (no model) then the follow-up window. **Rejected:** training a new openWakeWord classifier in-app (Python, synthetic data, hours), a cloud wake word (audio would leave the PC all the time), Porcupine custom keywords in-app (Console account and per-version `.ppn` files; Sir can still pick Picovoice's built-in "Jarvis").

### ADR-039: Voice Match and learned name spellings (v2.14)

### ADR-037: Sub-agents and smaller v2.12 features
